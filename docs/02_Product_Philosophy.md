# 📘 LIA-Make

# Product Philosophy

> "La mejor tecnología es aquella que desaparece y permite que las personas se concentren únicamente en crear."

---

# Introducción

LIA-Make no es un generador de código.

No es un IDE.

No es un Low-Code Builder.

No es un No-Code Builder.

LIA-Make es una plataforma para **crear software visualmente**, donde la inteligencia artificial elimina la complejidad técnica sin eliminar la satisfacción de construir.

Cada decisión dentro del producto deberá respetar esta filosofía.

---

# Nuestra Filosofía

## La IA trabaja.

## El usuario crea.

La IA debe encargarse de las tareas repetitivas.

El usuario debe concentrarse únicamente en las decisiones importantes.

---

# Principios Fundamentales

---

# 1. La IA propone.

Nunca impone.

Cada pantalla.

Cada formulario.

Cada componente.

Cada descripción.

Cada imagen.

Cada README.

Cada campaña de marketing.

Cada arquitectura.

Debe comenzar con una propuesta inteligente.

El usuario siempre tendrá la última decisión.

---

# 2. Nunca mostrar una hoja en blanco.

Las hojas en blanco generan incertidumbre.

Todo comenzará con una primera propuesta.

Aunque posteriormente pueda modificarse completamente.

---

# 3. El usuario siempre debe sentir que él construyó la aplicación.

Aunque la IA escriba miles de líneas de código.

Aunque genere automáticamente documentación.

Aunque cree imágenes.

Aunque genere el backend.

El usuario debe sentir que él tomó las decisiones.

Porque la satisfacción de crear es parte de la experiencia.

---

# 4. Todo debe ser visual.

La arquitectura debe verse.

Las conexiones deben verse.

Los errores deben verse.

Los costos deben verse.

Las dependencias deben verse.

La programación debe comprenderse visualmente.

---

# 5. Todo debe ser comprensible.

Los usuarios no deberían aprender nombres de errores.

No deberían memorizar excepciones.

No deberían leer mensajes técnicos.

La plataforma debe explicar los problemas utilizando lenguaje humano.

---

# Ejemplo

Incorrecto

Null Pointer Exception

Correcto

"La pantalla Perfil está esperando un usuario, pero todavía nadie se lo ha enviado."

---

# 6. El proyecto siempre pertenece al usuario.

LIA-Make nunca bloqueará la libertad del creador.

Los usuarios podrán:

- exportar
- modificar
- vender
- instalar
- alojar
- compartir

sus proyectos donde ellos decidan.

---

# 7. Reducir la fricción.

Cada paso innecesario deberá desaparecer.

Si una tarea puede automatizarse sin afectar la creatividad del usuario, deberá hacerlo.

---

# 8. Cada clic debe justificar su existencia.

Antes de agregar un botón debemos preguntarnos:

¿Realmente aporta valor?

Si la respuesta es no.

Debe eliminarse.

---

# 9. Aprender haciendo.

LIA-Make no enseñará programación mediante cursos.

La enseñará mientras el usuario construye.

Cada nodo.

Cada conexión.

Cada explicación.

Será una oportunidad de aprendizaje.

---

# 10. La IA nunca reemplaza al usuario.

La IA acompaña.

Sugiere.

Explica.

Optimiza.

Pero nunca toma el control creativo del proyecto.

---

# 11. Todo tiene un punto de partida.

Los usuarios nunca comenzarán desde cero.

Siempre recibirán:

- una propuesta
- una estructura
- un diseño
- una descripción
- un flujo

Que podrán modificar libremente.

---

# 12. El software debe sentirse vivo.

Las aplicaciones no deben sentirse estáticas.

El Canvas.

Los nodos.

Las conexiones.

El compañero IA.

Las transiciones.

Las animaciones.

Todo debe transmitir vida.

---

# 13. La simplicidad siempre gana.

Si existen dos maneras de realizar una tarea.

Siempre elegiremos la más sencilla.

Aunque técnicamente sea más compleja de implementar.

---

# 14. La documentación debe construirse automáticamente.

Mientras el usuario crea.

LIA-Make deberá generar automáticamente:

- README
- Arquitectura
- Dependencias
- Tecnologías
- Costos
- Casos de uso
- Roadmap
- Historial del proyecto

La documentación nunca deberá convertirse en una carga.

---

# 15. El Marketplace comienza desde el primer día.

Cada decisión deberá considerar que la aplicación podría venderse.

Por ello.

La plataforma preparará automáticamente:

- capturas
- descripción
- icono
- banner
- SEO
- precio sugerido
- material promocional

---

# 16. La IA elimina el trabajo repetitivo.

Nunca eliminará la creatividad.

Ese equilibrio define toda la experiencia.

---

# 17. Pensar como un creador.

No como un programador.

Las personas no quieren crear clases.

Quieren crear:

- negocios
- soluciones
- productos
- ideas

LIA-Make siempre hablará el lenguaje del creador.

---

# 18. La experiencia vale más que la tecnología.

Los usuarios nunca recomendarán LIA-Make por Flutter.

Lo recomendarán porque crear una aplicación fue divertido.

---

# Nuestra Promesa

Si un usuario termina una aplicación deberá poder decir:

> "Nunca pensé que crear software pudiera sentirse tan fácil."

---

# Regla Suprema

Antes de implementar cualquier nueva función debemos responder tres preguntas.

1.

¿Hace la plataforma más sencilla?

2.

¿Hace que el usuario aprenda mientras crea?

3.

¿Hace que el usuario disfrute construir?

Si alguna respuesta es NO.

La función deberá replantearse.

---

# Mantra del Equipo

No construimos herramientas.

Construimos confianza.

No escribimos código.

Construimos experiencias.

No automatizamos personas.

Potenciamos creadores.
