# 04 — Node Animations

> Motion is communication.
>
> Every animation must explain something.

---

# Introduction

Animation is one of the pillars of the LIA-Make experience.

Nodes should never move randomly.

Every transition,
every glow,
every pulse,
every movement exists for one purpose:

To communicate.

Animations are not decoration.

Animations are language.

---

# Philosophy

The interface should feel alive.

Not busy.

Not distracting.

Alive.

The user should understand what is happening simply by observing movement.

Motion replaces explanation.

---

# Design Goals

Animations should be:

• Fast

• Elegant

• Natural

• Responsive

• Purposeful

• Consistent

Never flashy.

Never chaotic.

Never exhausting.

---

Real Time

# Animation Categories

## Passive

Always running.

Very subtle.

Examples

Idle breathing.

Tiny glow.

Energy shimmer.

---

## Reactive

Triggered by the user.

Examples

Hover.

Click.

Selection.

Drag.

Drop.

---

## System

Triggered by LIA.

Examples

Execution.

Validation.

Compilation.

Generation.

Thinking.

---

## Environmental

Background animations.

Grid.

Particles.

Ambient lighting.

Very low intensity.

---

# Hover Animation

The node reacts immediately.

Effects

Scale

102%

Shadow increases

Glow appears

Border becomes brighter

Duration

150 ms

Curve

Ease Out

The user should instantly know

"This node is interactive."

---

# Selection Animation

The node confirms selection.

Effects

Quick pulse

Border expands slightly

Glow strengthens

Connection ports appear

Duration

200 ms

The node should feel acknowledged.

---

# Drag Animation

The node leaves the surface.

Effects

Scale

105%

Shadow doubles

Node lifts

Very small rotation

Cursor becomes magnetic

Nearby compatible ports illuminate

The node feels physical.

---

# Drop Animation

The node returns to the canvas.

Effects

Small bounce

Shadow returns

Rotation resets

Glow stabilizes

Duration

180 ms

Should feel satisfying.

---

# Connection Animation

The connection should never appear instantly.

Effects

Cable grows toward destination

Port glows

Magnetic snap

Tiny energy pulse

The user should feel two systems becoming one.

---

# Invalid Connection

Effects

Tiny shake

Brief red flash

Connection retracts

Duration

120 ms

No punishment.

Only information.

---

# Execution Animation

Applications become alive.

Connections transport particles.

Nodes illuminate one after another.

Outputs pulse.

Energy travels through the workflow.

Execution becomes visible.

---

# AI Thinking

Unique to AI nodes.

Effects

Slow rotating particles

Inner glow

Moving holographic ring

Very subtle pulse

The node appears to reason.

Not simply wait.

---

# Success Animation

Effects

Green pulse

Soft expanding glow

Quick shine

Fade naturally

Duration

300 ms

Should reward the user.

---

# Error Animation

Effects

Red glow

Short vibration

Connection pauses

Error icon appears

The node asks for attention.

Never panic.

---

# Warning Animation

Effects

Amber pulse

Very slow breathing

Soft attention effect

Not urgent.

Just informative.

---

# Disabled Animation

None.

The absence of movement communicates inactivity.

---

# Premium Animation

Rare.

Elegant.

Crystal reflection.

Very slow shimmer.

The node feels valuable.

Never excessive.

---

# Celebration Animation

When the user completes something important.

Examples

First project.

First workflow.

First AI.

Successful build.

Effects

Soft particles

Gentle light

Short celebration

Professional.

Never childish.

---

# Ambient Motion

The interface itself breathes.

Examples

Very slow moving background lights.

Tiny particle fields.

Grid depth.

Subtle reflections.

Almost invisible.

The user notices only when looking carefully.

---

# Motion Hierarchy

The eye follows movement.

Therefore:

Important animations

↓

Medium animations

↓

Ambient animations

Nothing should compete for attention.

---

# Animation Curves

Preferred

Ease Out

Ease In Out

Spring

Physics

Avoid

Linear

Abrupt transitions

Mechanical movement

---

# Performance Goals

Animations should maintain:

60 FPS minimum.

120 FPS when hardware allows.

Animations should degrade gracefully on low-end devices.

Fluidity always takes priority over visual complexity.

---

# Emotional Design

Animations should make users feel:

Curiosity

Confidence

Satisfaction

Momentum

Achievement

Never anxiety.

Never stress.

Never confusion.

---

# Future Effects

Potential future additions

Soft reflections

Dynamic lighting

GPU particles

Flow simulation

Volumetric glow

Energy beams

Glass effects

Holographic projections

Depth blur

3D transitions

Only if performance remains excellent.

---

# Golden Rule

Every animation must answer one question:

"What information does this movement communicate?"

If the answer is:

"Nothing."

The animation should not exist.

---

# Final Thought

Motion is one of the most powerful teaching tools.

A great interface explains itself through movement.

The user should feel the software before understanding it.

---

# Manifesto

Beautiful motion is not decoration.

Beautiful motion is understanding made visible.
